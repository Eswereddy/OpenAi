5 How this scales beyond a hackathon demo

Keeping scheme data current. Today the 17 schemes are hand-curated from public criteria. A real deployment would start with a small team maintaining scheme rules as structured, version-controlled data — reviewed quarterly against myScheme.gov.in and state portals — then move toward a formal data-sharing arrangement with myScheme's own team, since they already aggregate this centrally. Longer-term, an LLM-assisted reader could parse official scheme notifications and PDFs and propose rule updates for human review, rather than requiring manual re-reading of every circular.

Reaching citizens with low connectivity or literacy. The UI's plain-language copy translates cleanly into regional languages. For feature-phone users — often exactly the population missing out on these schemes — an SMS/IVR channel could accept a few basic details by text and return matched schemes the same way, no smartphone or data connection required. The on-device offline fallback already running in this prototype (see the live/offline indicator after checking eligibility) is a working first step in that direction, not a hypothetical.

Turning usage into accountability. Every match is logged anonymously — age band, state, occupation, which schemes matched — with no name or ID ever stored. Aggregated, this becomes a live map of which schemes are least discovered in which regions: useful for a state welfare department deciding where to run outreach, not just a citizen-facing tool.

6 Built with
Built using Codex as part of Anthropic/OpenAI's Build What Moves India hackathon. The rules engine, the Express/SQLite backend, and the offline-fallback logic were all developed and iterated on with Codex assistance.
What's real here, and what's mocked?

Actually working:

  • A real backend (Node/Express) with a rule-based eligibility engine
  • A real SQLite database serving scheme data and logging anonymised match stats
  • Explainable results with a live/offline indicator
  • Falls back to on-device matching if the connection is slow

Mocked for this demo:

  • The 17 schemes use publicly known, general criteria — not a live government feed
  • No OTP, payment or ID verification, by design
